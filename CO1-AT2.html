Campus Service Helpdesk

The Campus Service Helpdesk is a web-based system through which students can report problems related to academics, accommodation, transportation, library facilities and other campus services.

Question 1: HTTP Header Error Analysis

Given Response

HTTP/1.1 200 OK
Date: Mon, 01 Apr 2026 10:00:00 GMT
Content-Type: text/html
Content-Length: -150
Connection: keep-alive
Incorrect Header Field:

The invalid field is Content-Length: -150. A content length represents the size of the response body in bytes, so it cannot contain a negative value.

Effect on the Browser

When the server returns the complaint confirmation page, the browser uses the Content-Length value to determine the expected size of the response. A negative value is invalid and can cause problems while processing the response.

Status Code

The status code 200 OK means that the server successfully processed the request. However, the response header itself contains an invalid Content-Length value.

Corrected Response

HTTP/1.1 200 OK
Date: Mon, 01 Apr 2026 10:00:00 GMT
Content-Type: text/html
Content-Length: 150
Connection: keep-alive

Question 2: DOM Tree and HTML Validation

Given HTML

<html>
<head>
<title>Service Helpdesk</title>
</head>
<body>

<section>
<p>Complaint received

</section>

</body>
</html>

Problem Identified

  • The paragraph element is missing its closing </p> tag.

How the Browser Handles It

Most modern browsers use their HTML parser to automatically recover from certain markup errors. Therefore, the missing closing paragraph element may be inserted automatically while constructing the DOM tree.

Possible Effects

  • The document is not properly written according to HTML syntax.
  • CSS selectors may produce unexpected results.
  • JavaScript DOM operations can become difficult to predict.
  • The page may still appear correctly in many browsers.

Corrected Markup

<section>
    <p>Complaint received</p>
</section>

Question 3: GET and POST Request Methods

Feature GET POST
Data Location URL query string HTTP request body
URL Visibility Data can be visible Data is not normally shown in URL
Typical Usage Retrieving information Submitting information
Suitable for Password No Yes, together with HTTPS

Major Difference

  • GET places submitted parameters in the URL.
  • POST transfers submitted data through the request body.

Recommended Method

For a student login or complaint submission form, POST is more appropriate because sensitive form information should not be placed directly in the URL.

Problems with GET for Login

  • Credentials may appear in browser history.
  • URLs may be recorded in server or proxy logs.
  • The URL can accidentally be shared with another person.
  • Sensitive information becomes visible on the screen.

Security Measures

  • Use the POST method for sensitive form submissions.
  • Use HTTPS to protect data during transmission.
  • Store passwords securely using hashing.
  • Use authenticated sessions.
  • Validate user input on the server.

Question 4: Finding Errors in HTML

Incorrect Code

<!DOCTYPE html>
<html>
<head>
<title>Campus Helpdesk</title>
</head>

<body>

<h1>Student Helpdesk

<p>Register your complaint

<img src="helpdesk.jpg">

</body>
</html>

Errors Found

  • The <h1> element has no closing tag.
  • The <p> element has no closing tag.
  • The image does not contain an alt attribute.

Why ALT Text is Important

The alt attribute provides alternative text when an image cannot be displayed and also improves accessibility for users who depend on screen readers.

Improved Image Element

<img src="helpdesk.jpg"
     alt="Student Campus Helpdesk">

Corrected HTML

<h1>Student Helpdesk</h1>

<p>Register your complaint</p>

<img src="helpdesk.jpg"
     alt="Student Campus Helpdesk">

Question 5: Browser to Server Communication

Communication Sequence

  1. The student enters the website address into the browser.
  2. DNS finds the IP address associated with the domain name.
  3. The browser establishes a connection with the required server.
  4. An HTTP request is sent to the web server.
  5. The server processes the requested resource or complaint.
  6. The server returns an HTTP response to the browser.
  7. The browser interprets the response and displays the webpage.

Possible Sources of Delay

  • Slow DNS resolution
  • Weak network connection
  • High server workload
  • Large image or video files
  • Unoptimized JavaScript

Purpose of DNS

DNS, or Domain Name System, translates a human-readable website name into the numerical IP address required by the browser to locate the appropriate web server.

Ways to Improve Website Performance

  • Use DNS caching.
  • Enable browser caching.
  • Compress and optimize images.
  • Minimize CSS and JavaScript files.
  • Use HTTPS efficiently.
  • Enable persistent connections.
  • Use a Content Delivery Network when required.

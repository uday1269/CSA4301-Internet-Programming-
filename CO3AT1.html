Question 1 – Student Registration using Servlet

Servlet architecture, GET/POST processing and servlet life cycle

Servlet Application Architecture

A Java web application receives an HTTP request from the browser. The servlet container identifies the required servlet and passes the request to it. The servlet processes the received parameters and produces an HTTP response for the browser.

GET and POST Request Handling

The GET method is mainly used for requesting information, while POST is commonly used when submitting form information. Registration details are better handled through POST because the form values are transferred in the request body.

RegistrationServlet.java 
import java.io.IOException;
import java.io.PrintWriter;

import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.*;

@WebServlet("/register")

public class RegistrationServlet extends HttpServlet {

    protected void doGet(
        HttpServletRequest request,
        HttpServletResponse response)
        throws IOException {

        response.setContentType("text/html");

        PrintWriter out =
            response.getWriter();

        out.println("<h2>Registration Page</h2>");

    }


    protected void doPost(
        HttpServletRequest request,
        HttpServletResponse response)
        throws IOException {

        String student =
            request.getParameter("student");

        String email =
            request.getParameter("email");

        response.setContentType("text/html");

        PrintWriter out =
            response.getWriter();

        out.println("<h2>Registration Completed</h2>");
        out.println("Student: " + student);
        out.println("<br>Email: " + email);
    }
}

Servlet Life Cycle

  1. init(): Called when the servlet is initialized.
  2. service(): Handles incoming client requests and dispatches them to appropriate methods.
  3. doGet()/doPost(): Perform processing based on the HTTP method.
  4. destroy(): Called before the servlet is removed so resources can be released.

Why POST is Preferred for Registration

POST places submitted form parameters in the request body instead of exposing them directly in the URL. However, POST by itself does not provide encryption. HTTPS should be used when sensitive information is transmitted.

Applications should also perform server-side validation and should never store passwords as plain text.

Question 2 – Session Management

Authentication state, HttpSession and session tracking

Session Tracking

HTTP is stateless, which means that each request is normally treated independently. Session management allows a web application to remember information about a particular user across multiple requests.

Login Servlet

After verifying the login credentials, the application can create an HttpSession and store the authenticated user's information as a session attribute. 

@WebServlet("/authenticate")

public class AuthenticationServlet
        extends HttpServlet {

    protected void doPost(
        HttpServletRequest request,
        HttpServletResponse response)
        throws IOException {

        String user =
            request.getParameter("username");

        String pass =
            request.getParameter("password");

        if ("admin".equals(user)
                && "java123".equals(pass)) {

            HttpSession session =
                request.getSession();

            session.setAttribute(
                "loggedUser", user);

            response.sendRedirect("dashboard");

        } else {

            response.sendRedirect("login.html");

        }
    }
}

Accessing the Session on Another Page 

HttpSession session =
    request.getSession(false);

if (session != null &&
    session.getAttribute("loggedUser") != null) {

    String user =
        (String) session.getAttribute("loggedUser");

    response.getWriter().println(
        "Welcome " + user
    );

} else {

    response.sendRedirect("login.html");

}

Logout and Session Invalidation

When a user logs out, the server should invalidate the current session so that previously stored authentication information is no longer available.

Question 3 – JDBC Product Management

Database connectivity, product insertion and retrieval

JDBC Architecture

JDBC stands for Java Database Connectivity. It provides Java applications with a standard mechanism for communicating with relational databases.

Java Application
→
JDBC API
→

MySQL Database

Steps for JDBC Connectivity

  1. Import the required JDBC classes.
  2. Establish a connection with the database.
  3. Create a PreparedStatement.
  4. Execute the required SQL command.
  5. Process the ResultSet for SELECT operations.
  6. Close resources after completing the operation.
  7. Handle SQL exceptions appropriately.

Creating the Product Database 

CREATE DATABASE shopdb;

USE shopdb;

CREATE TABLE product (
    product_id INT PRIMARY KEY AUTO_INCREMENT,
    product_name VARCHAR(100) NOT NULL,
    product_price DECIMAL(10,2) NOT NULL,
    stock_count INT NOT NULL
);

Inserting a Product using JDBC 

public void addProduct(
        String name,
        double price,
        int stock) {

    String sql =
        "INSERT INTO product " +
        "(product_name, product_price, stock_count) " +
        "VALUES (?, ?, ?)";

    try (
        Connection connection =
            DriverManager.getConnection(
                DB_URL,
                DB_USER,
                DB_PASSWORD
            );

        PreparedStatement statement =
            connection.prepareStatement(sql)
    ) {

        statement.setString(1, name);
        statement.setDouble(2, price);
        statement.setInt(3, stock);

        statement.executeUpdate();

    } catch (SQLException ex) {

        System.out.println(
            "Database operation failed: "
            + ex.getMessage()
        );
    }
}

Retrieving Product Records 

String sql =
    "SELECT product_id, product_name, " +
    "product_price, stock_count FROM product";

try (
    Connection connection =
        DriverManager.getConnection(
            DB_URL,
            DB_USER,
            DB_PASSWORD
        );

    PreparedStatement statement =
        connection.prepareStatement(sql);

    ResultSet result =
        statement.executeQuery()
) {

    while (result.next()) {

        int id =
            result.getInt("product_id");

        String name =
            result.getString("product_name");

        double price =
            result.getDouble("product_price");

        int stock =
            result.getInt("stock_count");

        System.out.println(
            id + " " +
            name + " " +
            price + " " +
            stock
        );
    }

} catch (SQLException ex) {

    System.out.println(
        "Unable to read product data."
    );
}

Servlet to Database Flow

In a layered Java web application, a browser request can reach a servlet, which calls a database-access component. JDBC then communicates with the database and returns the result back through the application.

Exception Handling and Security

  • Use try-with-resources to close JDBC resources.
  • Handle SQLException without exposing technical database details to users.
  • Use PreparedStatement for parameterized queries.
  • Validate product information before insertion.
  • Avoid hard-coding production database credentials.
  • Connection pooling can improve performance for applications with many users.

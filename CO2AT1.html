Experiment 1: Responsive Web Layout

(a) Reasons for poor responsiveness

  • Fixed-width elements may not fit smaller screens.
  • The viewport setting is necessary for proper mobile scaling.
  • Absolute positioning can cause elements to overlap.
  • Images can overflow when their width is not restricted.
  • Without media queries, the same desktop design remains on smaller devices.
  • Incorrect Grid or Flexbox settings can create spacing problems.

(b) Responsive design using CSS Grid and Flexbox

CSS Grid is useful for arranging repeated content such as products and experiment cards. Flexbox is suitable for one-dimensional arrangements such as headers, navigation and side-by-side content.

(c) Desktop, tablet and mobile adaptation

  • Desktop: Three columns are displayed for the product area.
  • Tablet: The layout changes to two columns using a media query.
  • Mobile: Elements are arranged in a single column.

(d) Spacing and alignment

Properties such as gap, padding, margin, justify-content, align-items and grid-template-columns are used to maintain a clean and consistent layout.

(e) Evaluation and improvements

The responsive layout allows the webpage to adapt to different screen sizes without unnecessary horizontal scrolling. Further improvements could include accessibility testing, responsive images and testing on multiple physical devices.

Experiment 2: JavaScript Form Validation

(a) Problems with simple validation

  • Checking only empty fields does not verify the actual format.
  • An incorrectly formatted email may be accepted.
  • Phone numbers may contain letters or an incorrect number of digits.
  • Users do not receive immediate feedback when typing invalid data.
  • Client-side validation should always be supported by server-side validation.

(b) HTML validation attributes

The registration form uses attributes such as required, type="email", minlength, maxlength and type="tel" to improve input validation.

(c) Regular Expression validation

A regular expression is used to check the basic structure of an email address. A separate pattern checks whether the entered phone number contains exactly ten digits.

(d) Real-time feedback

The JavaScript code monitors user input. When an invalid value is entered, an error message appears immediately and the input border changes to indicate the problem.

(e) Improvements

Real-time validation improves usability. A production application should additionally use server-side validation, input sanitization, HTTPS, rate limiting and proper email verification.

Experiment 3: CSS Layout Debugging

(a) Causes of overlapping elements

  • Improper use of absolute positioning.
  • Fixed widths that exceed the available screen width.
  • Negative margins that move elements over each other.
  • Excessive padding or borders.
  • Lack of responsive rules for smaller screens.

(b) CSS Box Model

The CSS box model consists of four main parts: content, padding, border and margin. Using box-sizing: border-box makes width calculations easier because padding and borders are included inside the declared width.

(c) Better positioning technique

Flexbox can be used instead of unnecessary absolute positioning. Flexbox keeps elements within the normal layout flow and allows them to adjust according to the available space.

(d) Preventing overlap

The corrected design uses Flexbox, flexible sizing, min-width:0 and media queries. On smaller screens, the sidebar and main content are placed vertically.

(e) CSS best practices

  • Prefer Flexbox and Grid for major page layouts.
  • Avoid unnecessary absolute positioning.
  • Use relative and flexible units when suitable.
  • Apply box-sizing: border-box.
  • Test the design at different screen widths.
  • Keep images within their containers.
  • Organize CSS rules clearly.
